# Store-only miniz fork

This tree is derived from [miniz](https://github.com/richgel999/miniz) **3.1.2**
but is a destructive, store-only fork. There is no Deflate/Inflate codec and no
zlib-style API: the corresponding source files, declarations, tests, examples
and fuzz targets have been removed. A store-only build is the only build; no
macro or CMake option can re-enable the codec.

## What remains

* `miniz.c` – ZIP64-capable reader, writer, appender, iterator, clone,
  validation and in-place update code, plus CRC-32, allocator helpers and
  `mz_version()`.
* `miniz.h` – single public header with shared types, allocator macros,
  little-endian helpers, the stored ZIP API, CRC-32 and compression-level
  constants kept for source compatibility.

`miniz_tdef.{c,h}` and `miniz_tinfl.{c,h}` no longer exist. Codec-only tests,
examples and fuzzers were deleted as well. The amalgamation (`amalgamation/`,
generated by the build) therefore contains no codec code.

`miniz_archive.h` was only an alias for `miniz.h` and has been removed.
`miniz_common.h` and `miniz_zip.h` were merged into `miniz.h`, and
`miniz_zip.c` was merged into `miniz.c`; the public API is now one header and
the implementation is one source file. Include `miniz.h` directly. The
remaining sources are kept compact: redundant comments, blank lines and
unreachable store-only branches were removed without changing public
signatures or ZIP behaviour.

## Behaviour

* **Reading:** only stored entries (method `0`) are supported. A non-zero
  method without `MZ_ZIP_FLAG_COMPRESSED_DATA` is rejected with
  `MZ_ZIP_UNSUPPORTED_METHOD` from file-stat support, extraction, iterator and
  validation paths.
* **Writing:** every entry is stored. A requested compression level greater
  than zero is accepted for API compatibility and ignored; the written method
  is `0`.
* **`MZ_ZIP_FLAG_COMPRESSED_DATA`:** keeps its upstream meaning for raw-copy
  callers. The supplied bytes are copied unchanged and tagged with method `8`.
  This is data movement, not a compressor: these entries cannot be read back
  as uncompressed data by this fork.
* ZIP64, timestamps, comments, extra fields, alignment, cloning and
  finalisation behave as in upstream. Stored archives are byte-compatible with
  upstream stored output.

`MINIZ_ARCHIVE_STORE_ONLY` is deliberately not required and has no effect. It
may be left in an existing build system as an ignored define.

## Build and test

```sh
cmake -S . -B _build/store -DBUILD_TESTS=ON -DBUILD_EXAMPLES=ON
cmake --build _build/store -j
ctest --test-dir _build/store --output-on-failure
scripts/check_store_only_symbols.sh _build/store

# Amalgamation plus Python corpus checks
./test.sh

# Header-only
cmake -S . -B _build/header -DBUILD_HEADER_ONLY=ON -DBUILD_TESTS=ON
cmake --build _build/header -j
ctest --test-dir _build/header --output-on-failure
```

## Diagnostics

* `scripts/check_store_only_symbols.sh <build-dir>` – rejects codec symbols,
  codec object files and codec identifiers in the sources.
* `scripts/sync-upstream.sh` – merges a new upstream branch and reruns the
  build and the symbol check. Codec files must be removed again and the split
  ZIP source folded into `miniz.c` after resolving such a merge.
* `.github/workflows/store-only.yml` – Linux (gcc/clang), amalgamation, macOS,
  MSVC x64/Win32 and MinGW 32/64 jobs.

## Rules for future edits

* Do not reintroduce codec source, declarations or build options.
* Keep the ZIP64 logic and public `mz_zip_*` signatures unchanged where
  possible.
* Non-stored entries must fail explicitly with `MZ_ZIP_UNSUPPORTED_METHOD`;
  never add a silent fallback or a codec stub.
* Keep the public API in the single `miniz.h`; do not reintroduce
  `miniz_common.h` or `miniz_zip.h`.
* Keep the implementation in the single `miniz.c`; do not reintroduce
  `miniz_zip.c`.
